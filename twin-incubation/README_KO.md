# GARD TWIN Independence Evidence Lab™ v1.0

**목적:** “내 도움이 없이도 다른 사람이 자기 1인 기업을 만들어 독립 운영하고, 그 사람이 다시 새로운 오너를 만들어낼 수 있는가?”를 증거에 근거해 검증하는 정적 웹앱.

## 실행 구조

- `index.html`: 누구나 열 수 있는 공개 설명과 실행 진입점
- `studio.html`: 사용자 자신의 1인 기업 제작, 다섯 독립 시험, 사적 이메일 협상 원장, 후속 오너 기록
- `engine.mjs`: 로컬 상태, 증거 상태 판정, JSON 교환, 공개 허용 목록, ZIP 생성 엔진
- `app.js`: 브라우저 로컬 저장·입력·다운로드·복원 UI
- `style.css`: 한국어·모바일 반응형 화면
- `netlify.toml`: **독립 저장소 루트**로 Netlify 배포할 때 사용할 정적 호스팅 설정

`studio.html`은 브라우저 LocalStorage에서 `gard_twin_independence_lab_v1` 키를 사용하며 오너·구독자 데이터가 중앙으로 전송되지 않습니다. **같은 브라우저·동일 사이트에서 여러 사람이 사용할 경우 데이터가 섞일 수 있으므로 별도 브라우저 프로필과 백업을 사용하십시오.** 민감 정보나 기밀 증거 원문은 입력하지 말고 증거 위치만 적으십시오. 로컬 스토리지는 암호화 금고가 아니며 같은 프로필의 타인이 접근 가능할 수 있습니다.

## 로컬 실행

```bash
cd twin-incubation
python -m http.server 8787
```

브라우저에서 `http://localhost:8787/index.html`을 엽니다. `file://` 직접 실행은 ES 모듈 정책으로 정상 작동하지 않을 수 있습니다.

## 실제 사용 시나리오

1. `내 1인 기업 시작` → 사업명/오너명/실제 고객 문제/가치(F)/고객 반론(C)/비AI 대안(X) 작성.
2. 직접 만든 첫 자산을 등록. 공개 가능 설명을 검토하고 자산별 공개 동의.
3. 다른 사람 도움 없이 제작한 증거, 다른 기기 복원 증거, 권리 결정, 독립 전시장, 실제 협상 기록을 5개 실증란에 입력.
4. 질문 JSON을 다운로드해 개인 이메일에 직접 첨부. 이메일/거래 원장에 실제 근거와 상태를 기록.
5. `공개·인도·백업` → 공개 승인된 내용만 담은 ZIP 다운로드. ZIP을 검수한 다음 **자신이 소유한 새로운 GitHub 저장소**의 루트에 `index.html`과 `catalog.json` 업로드.
6. Netlify에서 GitHub 저장소를 Import → Build command 비움, Publish directory `.` 선택 → 배포 완료 후 본인이 실제 URL 접속·기기 변경·복원을 검증.
7. 자신이 도운 후속 창업자가 다시 자기 전시장을 운영하면 2세대 오너 원장에 증거와 별도 검토 내용을 등록.
8. `비공개 전체 원장 JSON`은 별도 다운로드하여 안전한 저장소에 보관. **GitHub/Netlify에는 절대 업로드하지 않음.**

## 이미 있는 GARD P2P 시장 저장소에 연결할 경우

대상 저장소: `ANN-KOREA/GARD-P2P-Asset-Market-2`

새 디렉터리 `twin-incubation/`만 추가하세요. 기존 `catalog.json`, `owner.html`, `buyer.html`, 원장·JS 등을 덮어쓰지 않습니다. 기존 Netlify가 `main` 브랜치에서 저장소 루트 `.`을 배포한다면 추가 페이지 주소는 `{현재 Netlify 사이트}/twin-incubation/`입니다. 배포 실패나 경로 설정이 다를 수 있으므로 실제 URL을 확인해야 합니다. 루트의 `netlify.toml`을 이 디렉터리 파일로 교체하지 마세요.

## 증거 상태의 정직성

- `NOT_TESTED`: 증거 없음
- `SELF_REPORTED`: 사용자 자신이 증거 참조와 실행 날짜를 남김
- `REVIEW_RECORDED`: 다른 검토자의 이름·메모가 입력됨. **검토자 신원·서명·독립성·증거의 진실성을 앱이 보증하지 않음.**
- 다섯 개 시험의 검토기록이 채워져도 실제 독립 운영이 인증되었다고 자동 선언하지 않음.
- 후속 창업자 정보가 입력되어도 두 번째 독립 창업이 입증되었다고 자동 선언하지 않음.
- 실제 이메일은 이 앱에서 자동 전송되지 않음; `mailto:`는 작성창만 여는 동작.
- 실제 입금/계약/실사 기록은 외부의 은행·당사자·검증자를 통해 확인해야 함.

## 보안과 통제

- 비공개 데이터는 브라우저의 로컬 데이터에만 저장. **공개사이트를 열어보는 방문자는 자기 브라우저의 별도 기록만 가짐.**
- `publicCatalog()`는 명시 공개 자산의 제목·설명·라이선스와 공개 승인한 이메일만 내보냄.
- 공개 전시장 ZIP의 HTML은 사용자 텍스트를 HTML-이스케이프하여 삽입함.
- 백업은 복원 직전 자동 다운로드하고 전체 교체는 추가 확인을 거침. 스키마 및 필수 객체 구조 검사하지만 고급 보안·악성 데이터 검사는 제공하지 않음.
- ZIP은 무압축 표준 ZIP이며 OS 기본 압축 도구로 열 수 있음.
- 암호화 저장, 인증, 결제, 전자서명, 외부 검증자 신원 확인, 자동 GitHub 업로드는 1.0 범위 밖.

## Netlify 배포 상태 구분

1. 이 ZIP 생성: **로컬 소스 완성**
2. GitHub 기능 브랜치와 PR: **저장소 반영 대기**
3. PR을 `main`으로 병합하고 기존 Netlify 사이트가 자동 빌드하거나 새 프로젝트 Import: **배포 연결**
4. 공개 URL 실제 접속과 실사용 시험: **운영 검증**

이 단계를 서로 혼동하면 안 됩니다. 공개 링크를 실제 검증하기 전에는 배포 완료로 말하지 않습니다.
