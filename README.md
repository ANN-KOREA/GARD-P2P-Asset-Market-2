# GARD Person-to-Person Asset Market™

**v1.2 (2026-11-15) — 오너 이메일 입력 UX와 공개 JSON 다운로드 접근성 개선.** 기존 사이트를 업데이트하는 경우에는 **PATCH ZIP(변경 파일 4개)**을 사용하세요. 이 전체 ZIP 안에는 **비어 있는 기본 `catalog.json`**이 들어 있어 기존 공개 내용을 덮어쓸 위험이 있습니다.

**GitHub → Netlify에 바로 배포할 수 있는 별도 저장소용 신규 구현.** 기존 GARD 저장소 코드를 가져오지 않았습니다. 외부 JS 라이브러리, 클라우드 API, 서버 DB, AI 계정, 빌드 단계 없이 실행됩니다.

> 공개 전시장은 모두에게 열고, 거래는 두 사람의 이메일 합의로 완성한다.

## 화면 구성

| 페이지 | 누가 사용하는가 | 역할 |
|---|---|---|
| `index.html` | 누구나 | 공개 승인 자산 검색, 상세 보기, 이메일 문의 초안 |
| `owner.html` | 자산 소유자 | 로컬 원본/첨부, 공개 승인, 거래 원장, 입금 수동 확인, 인도 ZIP, 백업/복원 |
| `buyer.html` | 구매자 | 이메일로 받은 인도 ZIP을 로컬에서 무결성 검사, 저장, 백업/복원 |

## 5분 실행

1. **새로운 GitHub 저장소**를 만듭니다. 이름 예: `GARD-P2P-Asset-Market`.
2. 이 프로젝트의 **파일과 폴더 전체를 저장소 최상위(root)**에 업로드합니다. **ZIP 파일 하나만 업로드하지 마세요. 압축을 풀어야 합니다.**
3. Netlify → **Add new project → Import an existing project → GitHub**로 저장소를 연결합니다.
4. Build command: **비움** / Publish directory: **`.`** (프로젝트 최상위) / Base directory: **비움**. `netlify.toml`에 설정되어 있습니다.
5. Netlify가 생성한 HTTPS 주소를 엽니다. `/owner.html` **상단 STEP 1: 오너 거래 문의용 이메일 등록**에 이메일을 입력하고 **이메일 저장**을 누릅니다. 이어 자산을 등록합니다.
6. 상태를 **PROMOTION**으로 변경하고 **명시적 공개 승인**을 체크하여 저장합니다.
7. **오너 스튜디오 첫 화면의 `↓ 승인 자산 JSON 다운로드`** 또는 **`자산 제작·관리` 하단 버튼**, 혹은 **`공개·배포` 탭**에서 `catalog.json`을 내려받습니다. **이 기능은 저장된 자산 상태를 기준**으로 작동하므로 먼저 `자산 저장`을 누르세요. 그런 다음 GitHub 저장소의 기존 `catalog.json` 파일을 새 내용으로 교체하고 커밋합니다.
8. Netlify 배포 완료 후 `/index.html`에서 실제 공개 내용을 확인합니다.

GitHub 신규 저장소 권장 이름: `ANN-KOREA/GARD-P2P-Asset-Market` (소스 저장소는 **private**로 만들어도 공개 Netlify 사이트 배포 가능). [GitHub 새 저장소 만들기](https://github.com/new)에서 이름을 지정하고 파일을 올리세요.

**기본 카탈로그는 비어 있습니다.** 소유자의 승인을 받지 않은 실물 자산, 이메일, 성과는 처음부터 공개하지 않습니다.

## 로컬 개발

Python 3이 있으면 (외부 의존성 없음):

```bash
python3 -m http.server 8080
```

`http://localhost:8080`에서 페이지를 열어 사용합니다. `file://`로 HTML을 직접 열면 브라우저 모듈 보안 정책 때문에 실행되지 않을 수 있습니다.

단위 테스트(Node.js 20+):

```bash
npm run preflight
```

브라우저 기능 검증: `docs/TESTING.md`.

Windows에서 새 저장소 생성부터 최초 Push까지 수행할 수 있는 선택적 스크립트: `scripts/Create-GitHub-Repo-Windows.ps1`. 자세한 사용법은 `docs/UPLOAD_GITHUB_NETLIFY.md`를 참고하세요. 이 스크립트는 별도 GitHub CLI 설치·로그인이 필요합니다.

정적 공개 자료는 `npm run check:catalog`에서 승인되지 않은 필드가 섞였는지 검사하며, `.github/workflows/qa.yml`의 GitHub Actions도 동일 검사를 수행합니다. 배포된 Netlify 사이트 자체와 실제 입금은 별도 시험 대상입니다.

## v1.2 업데이트 — 오너 공개 이메일 입력 위치 개선

- 오너 스튜디오 메인화면 통계 바로 아래에 **STEP 1: 오너 거래 문의용 이메일 등록** 입력창·저장 버튼을 상시 노출합니다.
- 이메일 저장 후 **STEP 2: 승인 자산 JSON 다운로드** 버튼을 활성화합니다. 미설정 상태에서는 해당 버튼을 비활성화하고 이유를 안내합니다.
- 저장한 이메일은 `설정·감사기록`에서도 확인·수정 가능하며 **두 화면은 동일한 브라우저 IndexedDB 설정을 사용합니다.**
- **오너 공개 문의 이메일은 `catalog.json`에 포함되어 인터넷에서 열람될 수 있습니다.** 구매자 이메일·원본 파일·거래 원장은 공개하지 않습니다.
- 사이트 배포 및 `catalog.json` 교체는 자동으로 이루어지지 않습니다. 기존 공개 이메일을 변경해도 GitHub에 새 JSON을 올리기 전까지 전시장에는 이전 주소가 남습니다.
- **기존 운영 데이터 유지:** DB 이름 `gard-p2p-market-2026-v1`을 바꾸지 않았습니다. 같은 Netlify 사이트 주소와 같은 브라우저 프로필에서 업데이트할 때 현재 IndexedDB 자료를 그대로 읽도록 설계했습니다. 배포 전 백업을 권장합니다.

## v1.1 업데이트 — 공개 JSON 다운로드 접근성

- 첨부 PDF에서 `자산 제작·관리`에 머물러 있을 때 공개 JSON 내보내기 버튼이 보이지 않던 문제를 개선했습니다.
- **오너 첫 화면 운영 통계 바로 아래**에 `↓ 승인 자산 JSON 다운로드`를 추가했습니다.
- 자산 등록·수정 폼의 **`자산 저장` 버튼 옆**에도 `↓ 저장된 승인 자산 JSON 다운로드`를 추가했습니다.
- 기존 `공개·배포` 탭의 다운로드·미리보기 기능은 그대로 유지합니다.
- 거래용 공개 이메일이 설정되어 있지 않으면 오류와 안내를 표시합니다. 공개 승인 자산이 0개일 때는 기존 공개 정보 삭제 위험을 알리고 확인 후 다운로드합니다.
- **중요:** `catalog.json`은 공개 홍보 자료 전용입니다. 비공개 자산·구매자 정보·거래 원장 백업과 혼동하지 마세요.
- 웹앱에서 버튼을 누르는 것만으로 GitHub 파일을 변경하거나 Netlify에 배포하지 않습니다.

## 거래 과정

1. 오너: 비공개 자산 등록 → 승인한 **홍보 필드만** 공개 JSON 생성.
2. 방문자: 자산 카드 탐색 → `mailto:`로 자신의 메일 앱에서 직접 문의.
3. 오너: 이메일 내용을 확인하고 거래 ID 생성 → 견적/협상/합의 기록.
4. 합의: 견적 참조번호, 이메일 동의 근거를 기록 → 입금 대기.
5. 은행에서 **오너가 직접 실제 입금 내역 확인** 및 근거 기록 → 입금 확인.
6. 오너: 인도 ZIP 생성 → 이메일로 직접 전달 → 전달 사실을 로컬 원장에 기록.
7. 구매자: ZIP을 `buyer.html`에 가져오기 → 파일 SHA-256 일치 확인 → 독립 저장.

거래 상태: `INQUIRY → DETAIL_SHARED → QUOTED ↔ NEGOTIATING → AGREED → AWAITING_PAYMENT → PAID_CONFIRMED → DELIVERED → BUYER_ACK`, 그리고 취소·분쟁 경로. 잘못된 자동 PASS를 허용하지 않습니다.

## 주의할 점

- Netlify의 정적 공개 주소는 **로그인 인증 기능을 제공하지 않습니다**. `/owner.html`에 접근한 다른 방문자는 자신의 브라우저 저장 영역에서 빈 오너 앱을 볼 뿐이지만, 다른 사람과 동일 기기·브라우저 프로필을 공유하면 데이터가 노출될 수 있습니다. 민감한 원본은 전용 기기·프로필에서만 작업하세요.
- 비공개 데이터는 이 프로젝트에 업로드하지 마세요. 특히 **GitHub public repo의 모든 파일은 공개**됩니다. `catalog.json`에 공개용 정보만 포함됩니다.
- **이메일은 자동 수집·전송하지 않습니다.** 메일 작성 앱이 열리고 이용자가 발송해야 합니다. 문의 기록도 오너가 수동으로 기록합니다.
- **입금 자동 확인·결제대행·분쟁 중재·저작권 인증은 제공하지 않습니다.** 실제 송금 여부는 금융기관에서 직접 확인합니다. 구매자 SHA-256 검증은 파일 일치 검사이지 저작권·판매자 신원 확인이 아닙니다.
- 브라우저 저장소는 캐시 삭제, 브라우저 프로필 삭제, 기기 장애 등으로 유실될 수 있습니다. 오너와 구매자는 정기적으로 원본 파일 포함 JSON 백업을 다운로드하세요.
- 공개 중단은 새 `catalog.json` 배포가 완료되어야 반영됩니다. 이미 제3자가 다운로드한 파일·검색 캐시·스크린샷은 원격으로 회수되지 않습니다.
- 공개 전에 개인정보 처리방침, 표시·고지 의무, 디지털 콘텐츠의 환불·취소·사업자 등록과 통신판매 관련 법적 요건을 별도 확인하세요.
- **무상(0원) 거래의 입금 확인 경로는 1차 MVP에서 지원하지 않습니다.** 유상 자산 거래를 우선 검증합니다.
- 코드에 임의의 타인 자산이나 판매 실적을 미리 생성하지 않았습니다. 예시 생성 버튼은 비공개 합성 데모입니다.
